# 導入手順

新しいプロジェクト（別の資格の学習ノートなど）に問題集作成キットを導入するときのチェックリスト。

## 1. skillをコピーする

- [ ] `skills/quiz-authoring/` を、導入先の `.claude/skills/quiz-authoring/` にフォルダごとコピーする
- [ ] 用語集・用語ノートも作るなら、`skills/term-note-authoring/` も同様にコピーする
- [ ] 導入先に同名のskillが既にある場合は、上書きする前に中身を確認する（そのプロジェクトで書き足した内容が消えないように）

## 2. project.mdを書き換える

コピーした `project.md` の「（記入）」をすべて埋め、「例（DP-300）」の行を削除する。最低限、次は決めておく。

- [ ] 対象試験と、短期目標・長期目標
- [ ] 出題形式の基本方針（選択式中心か記述式中心か）と、問題の区分。既存の問題集があるなら、その形式に合わせる
- [ ] 教材（原文）の場所。原文が手元にないなら、どこを根拠にするか（公式ドキュメントのURLなど）
- [ ] 問題集・成績と進捗・改善記録の置き場所
- [ ] 用語表記ルール（英語名を主にするか、日本語を主にするか）
- [ ] 試験対策問題集を使うか。使うなら優先度基準
- [ ] 本試験の出題形式の傾向（未受験なら「不明」とし、公式の出題形式情報が分かれば書く）
- [ ] 導入した版（README.mdの現在の版）

迷う項目は空欄にせず「未定」と書く。skillは未定の項目を推測で埋めず、ユーザーに確認する。

## 3. 導入先のCLAUDE.mdに一言書く

skillは自動で呼び出されるが、CLAUDE.mdにも参照を書いておくと確実に使われる。

```markdown
## 問題集作成のルール

問題集の新規作成・改訂・出題運用・レビューは `.claude/skills/quiz-authoring/SKILL.md` に従う。プロジェクト固有の設定は同フォルダの `project.md` にある。
```

## 4. ディレクトリを用意する

- [ ] project.mdに書いた置き場所のうち、まだ存在しないディレクトリを作る（問題集、改善記録など）

## 5. 動作を確認する

- [ ] 新しいセッションで「〇〇の問題集を作って」と依頼し、quiz-authoring skillが呼び出されるか確認する
- [ ] 最初の数問について、project.mdの設定（用語表記・出題形式）が反映されているか確認する

## 6. 運用中に教訓が見つかったら

- どの問題集にも通じる教訓 → 原本（DP-300ボールトの `問題集作成キット/`）に戻し、版数を上げてREADME.mdの更新履歴に書く
- そのプロジェクト固有の教訓 → 導入先のproject.mdか改善記録に書く
