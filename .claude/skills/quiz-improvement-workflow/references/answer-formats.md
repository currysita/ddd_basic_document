# 解答方法のまとめ

問題を直すとき、「何を確かめたいか（ねらい）」から、答えさせる形を選ぶための参照文書。問題文だけを直しても答えづらさが消えないとき、答え方そのものを変える案を探すために使う。

答え方を変えるのは、手段である。目的は、実装するとき、DDDに基づいた設計を実行できる状態になること。書く手間や言い回しの合否が、確かめたい力を邪魔していないかを基準に選ぶ。

## 1. 確かめたい力から形式を選ぶ

| 確かめたい力 | 向く形式（下の表のID） |
|---|---|
| 用語・定義の要点を言える | F2 一言、F3 語群つき穴埋め、F4 単一選択 |
| 似た概念・要因を見分けられる | F4、F5 複数選択、F7 分類、F8 対応づけ |
| 状況から誤り・不足に気づける | F9 誤りの指摘、F10 欠けているものの指摘 |
| 理由・仕組みを説明できる | F1 記述、F6 ○×＋理由 |
| 状況に応じて判断・設計できる | F12 判断・設計、F7 分類 |
| 手順の流れが分かる | F11 並べ替え（順序に必然性があるときだけ） |

## 2. 形式の一覧

| ID | 形式 | 答え方 | 弱点と対策 | このリポジトリの例 |
|---|---|---|---|---|
| F1 | 記述 | 自分の言葉で書く | 数・観点・長さが決まらない。問題文で「2つ」「1文で」「〜の観点から」と指定する | A-05、A-07、E4-07、E4-08 |
| F2 | 一言 | 一言・一語で答える | 言い回しがぶれる。答えが1つに決まる問いだけにして、採点の目安を足す | （なし） |
| F3 | 語群つき穴埋め | 空欄に、語群から語句を入れる | 空欄が1つだと勘で当たる。空欄は2つ以上、語群は空欄より多くする。完成文を読んで自然か確かめる | （なし） |
| F4 | 単一選択 | 3〜4択から1つ選ぶ | 紛らわしい誤答が作れないと、常識で当たる。定義が広い概念は向かない。誤答は教材の別の箇所・よくある誤解から作る | （なし） |
| F5 | 複数選択 | 当てはまるものをすべて／n個選ぶ | 選ぶ数を示すか決めておく。選択肢に、他の選択肢の語を入れない | E4-04（9つから6つ）、E4-09（4つから2つ） |
| F6 | ○×＋理由 | 正誤を答え、理由を1文で書く | 正誤だけだと勘で当たる。理由の欄を必ず付ける | （なし） |
| F7 | 分類 | 項目を2つ以上の分類先に振り分ける | 振り分けだけだと勘で当たる。使わない分類先を混ぜる、決め手を1文書かせる | E4-06、A-06-1 |
| F8 | 対応づけ | 状況とルール・要因を結びつける | 1対1の最後が消去法で決まる。余りの選択肢を混ぜる。状況ごとに、当てはまるルールが1つだけになるようにする | E4-05（ルール番号で答える） |
| F9 | 誤りの指摘 | 誤った発言・設計を示し、誤りと直し方を答える | 発言に答えの語が入りやすい（R6の軽度）。誤りの数を問題文で示す | A-02、A-04-3 |
| F10 | 欠けているものの指摘 | 状況から、欠けているもの・見失われているものを答える | 状況文の語が答えに近いと常識で解ける。守られている項目も混ぜる | A-12、A-13 |
| F11 | 並べ替え | 手順を正しい順に並べる | 順序に必然性がないものは使えない。本固有の番号の暗記にならないよう、手順は問題文に示す | （なし） |
| F12 | 判断・設計 | 状況を与え、判断・設計を述べる | 判断の観点が教材にあるか確かめる。教材にない判断を正解にしない | E4-09 の後半、応用問題 |

## 3. 書式の例（A-02「ドメインエキスパートの決め方」を題材に）

**F5 複数選択**

> 次のうち、DDDでドメインエキスパートになりうる人を、すべて選んでください。
> A. 業務の問題を最もよく知るプログラマ　B. 業務の問題を最もよく知る経営者　C. 特定の役割（ロール）で、業務の問題を最もよく知る人　D. 役職が部長であれば、誰でも
>
> 答え：A、B、C（Dは、役職で決める考え方）

**F3 語群つき穴埋め**

> ドメインエキスパートは、（①）ではなく、業務の（②）を最もよく知る人で、（③）にわたることが多い。
> 語群：役職／年齢／問題／システム名／1人／複数人
>
> 答え：①役職、②問題、③複数人

**F6 ○×＋理由**

> 「ドメインエキスパートは、組織で最も役職が高い人が務めるものだ」。正しいか誤りか答え、理由を1文で書いてください。

**F9 誤りの指摘（今の A-02）**

> 「業務部で一番役職が高いのは部長なので、ドメインエキスパートは部長1人とする」と決めました。この決め方がずれている点を2つ挙げ、それぞれ正しい考え方を答えてください。

## 4. 選択肢・語群を作るときの共通ルール

- 誤答は、教材の別の箇所の内容や、よくある誤解から作る。思いつきの誤答や、明らかに違う誤答は、勘で当たる原因になる
- 選択肢の記号は、ア・イ・ウ か A・B・C で統一し、全選択肢に付ける
- 否定形の選択肢を2つ以上並べない。問題文が「当てはまらないものは」のような二重否定にならないようにする
- 選択肢に、他の選択肢の語をそのまま含めない（「AとBの併用」のような選択肢は作らない）
- 正解の並びに規則性を作らない（上から順に当てはめれば正解、にしない）
- 選択肢の長さをそろえる。正解だけ長く丁寧だと、見た目で当てられる
- 状況文や問題文に、答えの語を入れない（R5、R6）
- 本固有の名前・番号を答えさせない。必要なら、問題文・選択肢に示す（R12）
- 模範解答の根拠は、教材（章まとめ・用語集）に必ずある

## 5. 欠陥の観点から、形式を選ぶ

| 欠陥（観点） | 形式を変える案 |
|---|---|
| R1 答えの形が不定 | F3、F4、F5、F7（選択肢・語群で形が決まる）。F1 のままなら、数と長さを指定する |
| R2 正解が複数 | F4、F5、F7（選択肢を限る） |
| R3 言い回しの再現 | F3、F4、F5、F7、F8（名前を示して選ばせる） |
| R4 一覧の書き出し | F9、F10、F7（状況・発言を示して判断させる） |
| R6 消去法・手がかり語 | F7・F8 に、使わない選択肢を混ぜる。F6 に理由欄を付ける |
| R9 採点がぶれる | F3、F4、F5（選ぶ形は、言い回しの採点が要らない） |
| R11 設計に結びつかない | F12、F9、F10、F7 |
| R12 本固有の暗記 | F7、F8（本固有の名前・番号を、問題文と選択肢に示す） |

## 6. このリポジトリでの使用状況と、決まっていないこと

- **決まり（2026-10-09）**：解答方法は制限しない。学習を効率化することが優先で、形式を制限すると不要な制限になるため（project.md の「出題形式の基本方針」）。以前の「記述式中心」の決まりは廃止した
- **条件**：形式は問題ごとに、ねらい（確かめたい力）に合わせて選ぶ。選択式・穴埋め・分類では、勘で当たらない工夫をする。形式を変えても、ねらいが変わらないことを確かめる
- E4-04（9つから6つを選ぶ）と E4-09（4つから2つを選ぶ）の複数選択の形は、この決まりで問題なくなった
