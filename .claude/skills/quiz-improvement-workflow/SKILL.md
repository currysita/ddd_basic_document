# 問題集の改善ワークフロー

このskillは、問題集の改善を**小さく区切って、毎回ユーザーの確認を挟みながら**進めるための手順書。

## なぜ小さく区切るのか

ユーザーは「全部やるとあなたは間違えるでしょう」と言っている。実際、一度に多くの問題を直すと、次のような間違いが起きやすい。

- 進捗ファイル（3周分）の更新漏れ、問題数・合計の計算ミス
- 自分で作った問題に、同じ欠陥（答えが複数ありうる、問題文が答えをばらす）を持ち込む
- 教材にない内容を模範解答に書き足す

だから1回の応答で扱うのは**1問だけ**にし、各段階の終わりで止まってユーザーの返事を待つ。急がない。

## 前提として読むもの

作業を始める前に、次を読む。読まずに書き始めない。

1. `.claude/skills/quiz-authoring/project.md`（このプロジェクトの決まり。習熟レベル、使える形式、ID規則、書式）
2. `.claude/skills/quiz-answerability-review/SKILL.md`（点検の10観点 R1〜R10）
3. 対象の問題ファイル `問題集/{カテゴリID}_*.md`
4. 対象章の `第XX章_*/第XX章まとめ.md` と `用語集/第XX章_用語集.md`（模範解答の根拠。これ以外を根拠にしない）
5. `問題集/レビュー記録/{カテゴリID}_レビュー記録.md`（あれば）

カテゴリと章の対応は `CLAUDE.md` のディレクトリ構成を見る（例: E4は第9章）。

## 全体の流れ

```
段階1 レビュー   → 報告して止まる
段階2 1問修正    → 見せて止まる（問題の数だけ繰り返す）
段階3 出題漏れ   → 1問追加して止まる（必要な数だけ繰り返す）
段階4 コミット   → ユーザーが頼んだときだけ
```

ユーザーが特定の問題だけを頼んだ場合（「E4-06を作り直して」）は、段階1をその1問だけで行い、段階2へ進む。

---

## 段階1：レビュー

1. 整合性チェックを実行し、作業前の状態を把握する：
   ```bash
   PYTHONIOENCODING=utf-8 python .claude/skills/quiz-improvement-workflow/scripts/check_consistency.py {カテゴリID}
   ```
   不一致があれば、レビュー結果と一緒に報告する（勝手に直さない）。
2. quiz-answerability-review の手順で、全問を1問ずつ点検する。
3. quiz-answerability-review の報告形式（要修正／採点の目安を追加／問題なし）で報告する。
4. 最後に「どの問題から直すか」をユーザーに聞いて**止まる**。

## 段階2：1問ずつ修正する

ユーザーが指定した1問（指定がなければ要修正の先頭）だけを扱う。

### 2-1. 下書きを作る

- 教材（章まとめ・用語集）の該当箇所を開き、模範解答に使う文を確認する。模範解答は教材の言葉で書く。教材にない理由・例・固有名詞を足さない
- **先に「ねらい」を1文で書く**。書けなければ、その問題が何を確かめるのか決まっていないので、ユーザーに相談する。書いたねらいから問題文と模範解答を作り、ねらいと食い違わないか確かめる
- 問題文は quiz-authoring の規則（1〜3文、シナリオは箇条書き、答えの数を問題文で指定）に従う
- 分割するときは枝番を付ける（`A-06` → `A-06-1`、`A-06-2`）。**後続のIDはずらさない**
- 分割した場合も、1回の応答で作るのは1問だけ。残りは次の応答で作る

### 2-2. 書く前に自己点検する

書いた問題文と模範解答を、quiz-answerability-review の R1〜R10 で点検する。とくに次の3つは、自分で作った問題でも繰り返し起きた。

- **R2**：教材の別の箇所や他の問題の答えも正解になりえないか
- **R5**：問題文の言葉が答えをばらしていないか
- **R6**：手がかり語・消去法・並び順で解けないか

当てはまったら直してから次に進む。

### 2-3. ファイルを更新する

次の順に更新する。1つも飛ばさない。

1. **問題ファイル**：問題を書き換える。模範解答の後ろに「ねらい」（必須）、「採点の目安」（必要なときだけ）、「備考」（根拠と未解決の課題）を書く。書式は `問題集/問題集作成_作業指示書.md` の「ファイルの構成フォーマット」に従う。問題数が変わったら、冒頭の「問題数」と内訳（知識確認・理解確認・応用の数）も直す
2. **進捗ファイル（第1周・第2周・第3周の3つすべて）**：
   - 該当行の「問題ID」「問題の観点」「習熟レベル」を問題ファイルに合わせる
   - 問題を追加・分割したら、行を正しい位置に挿入する
   - サマリー表のカテゴリ問題数と、合計の行を直す
   - すでに結果が記録されている問題を作り直した場合は、結果列を空にし、メモ列に `改訂前の問題（YYYY-MM-DD改訂）での結果：{結果}（{元のメモ}）` と残す（問題が変わったので再出題されるようにするため）
3. **レビュー記録** `問題集/レビュー記録/{カテゴリID}_レビュー記録.md`：判定表に1行追加する（ID／判定／指摘と修正内容）。表の外に行を書かないよう、追記後に表が途切れていないか見る
4. **作業履歴** `作業履歴.md`：末尾に次の形で追記する。番号は直前の作業番号＋1

   ```markdown
   ---

   ## 作業NNN：{何をしたか}

   **日付**：YYYY/MM/DD

   - {変更内容を1〜2行}
   - 変更ファイル：`...`、`...`
   ```

### 2-4. 機械的に確かめる

```bash
PYTHONIOENCODING=utf-8 python .claude/skills/quiz-improvement-workflow/scripts/check_consistency.py {カテゴリID}
```

作業前からあった不一致以外に、新しい不一致が出ていないことを確かめる。出ていたら直してから報告する。

### 2-5. 見せて止まる

次の形で報告し、**止まる**。次の問題には、ユーザーの返事を受けてから進む。

```markdown
{ID} を作り直しました。

> （改訂後の問題文と模範解答をそのまま引用）

**変えたところ**
- （何をどう直したか。どの観点 R? の欠陥を解消したか）

**ねらい**：（書いた1文）

**根拠**：[第XX章まとめ.md:行](パス#L行) の「…」

**採点で迷いそうな点**
- （言い換えとして認めるもの。なければ「なし」）

**更新したファイル**：問題ファイル、第1〜3周の進捗ファイル、レビュー記録、作業履歴
整合性チェック：新しい不一致なし

問題文に違和感がなければ、次は {次のID} に進みます。
```

## 段階3：出題漏れを追加する

1. 用語集の見出し語と章まとめの節見出しを一通り見て、問題文または模範解答の**主題**になっていない論点を候補として挙げる
2. 候補ごとに、既存問題と重なっていないか、教材に根拠のある問い方ができるか（一覧の書き出しにしかならないなら優先度を下げる）を判定し、ユーザーに候補と推奨を示して**止まる**
3. ユーザーが選んだ1つだけを、段階2と同じ手順（2-1〜2-5）で追加する。新しい問題はカテゴリの末尾に次の連番で置く

## 段階4：コミット

ユーザーが頼んだときだけコミットする。`main` ブランチに直接コミットする（CLAUDE.md の方針）。コミットメッセージは「何を・なぜ」を1行目に書き、変更点を箇条書きで続ける。

## 迷ったときは

- 教材に根拠が見つからない → 推測で書かず、ユーザーに「教材にはこう書いてあり、ここから先は書かれていない」と伝えて相談する
- 問題を削除・統合すべきか迷う → 自分で決めず、案を2つ示して選んでもらう
- すでに記録された結果の扱いに迷う → 2-3 の既定（結果列を空にしてメモに残す）を使い、報告で明示する
