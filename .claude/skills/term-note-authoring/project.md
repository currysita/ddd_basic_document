# プロジェクト設定（term-note-authoring）

このプロジェクト固有の設定。SKILL.mdと食い違う場合は、このファイルが優先される。キットを更新するときは、このファイルを退避してからSKILL.mdを上書きする。教材の場所・用語表記など、quiz-authoringと共通する項目は `../quiz-authoring/project.md` を参照する。

## 置き場所

| 種類 | 場所 |
|---|---|
| 用語集 | `用語集/第XX章_用語集.md`（章ごと）、全章統合は `用語集/用語集.md`。単元は章とする |
| 用語ノート | `用語集/用語ノート/<概念名>.md`（例: `用語集/用語ノート/集約の境界設計.md`）。最初のノートを作るときにフォルダを作る |
| 原文 | `第XX章_*/第XX章まとめ.md`（quiz-authoring/project.md「教材と単元の構成」参照） |
| 学習メモ | `問題集/学習メモ/{カテゴリID}_{カテゴリ名}.md`。問題ごとの誤答理由と質疑応答のメモであり、用語ノートとは別物。用語ノート化のきっかけ（SKILL.md 2節）を探すときの材料にする |

## 用語集の書式

既存の用語集に合わせる。五十音の見出し（`## あ行`）の下に `### 日本語名（English）` → 説明の段落を置き、項目間を `---` で区切る。英数字で始まる用語は末尾にまとめる。章の用語集に項目を追加したら、`用語集/用語集.md` にも反映する。

## 用語表記

quiz-authoring/project.md参照（日本語の訳語を主表記にし、英語は括弧書きで補う）。

## 表示環境と使える表現形式

- GitHubリポジトリ（VS Codeでも閲覧）。GitHubで表示できるmermaid（flowchart・quadrantChartなど）は使ってよい
- Obsidian固有の記法（`[[ ]]`、コールアウト）は使わない。リンクは通常のMarkdownの相対リンク（`[集約](../第10章_用語集.md#集約aggregate)` など）で書く
- 問題集との相互リンク（SKILL.md 3節の手順5）は、問題ID（例: `E1-03`）とカテゴリファイルへの相対リンクで示す
